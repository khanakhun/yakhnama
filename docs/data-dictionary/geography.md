# Data dictionary: geography

The `geography` module holds the administrative hierarchy, places and their names in
several languages and scripts. It was introduced in Phase 1. Column conventions are in
[README.md](README.md). **Proposed** marks a default the maintainer has not confirmed
yet; the open questions at the end of this page list each one.

Source code: `src/yakhnama/modules/geography/domain/`.

## Place (aggregate root)

One named location in the administrative hierarchy (glossary: Place). A place is never
deleted. It is retired or merged instead, so every record that refers to it can still be
resolved.

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `id` | `UUID` (v7) | — | Stable identity of the place. | Generated by the platform's `IdGenerator` at creation. | Phase 1 |
| `code` | `PlaceCode` (`str`, 2–64) | — | Stable machine code, for example `pk.gb.hunza`. Unique among places and never reused. Lower-case ASCII letters, digits, `_`, `.`, `-`, starting with a letter or digit. The dotted "parent path" style is a reference-data convention, and the domain does not enforce it. **Proposed** scheme. | Reference data file, or the moderator creating the place. | Phase 1 |
| `level` | `AdminLevel` | — | Administrative level. See the `AdminLevel` table below. | Reference data or moderator. | Phase 1 |
| `parent_id` | `UUID` (v7), nullable | — | The enclosing place. It is null for a country and required for every other level. The parent must be at a strictly higher level, and levels may be skipped (**proposed**, see Q-G4). A place is never its own parent. | Reference data or moderator. | Phase 1 |
| `names` | list of `PlaceName`, 1–64 | — | Every name of the place in insertion order. There is at least one. No two names share `(text, language, script)`. There is at most one preferred name per language. The bound of 64 is **proposed**. | See `PlaceName`. | Phase 1 |
| `geometry` | `PlaceGeometry`, nullable | degrees (WGS84) | The footprint: a GeoJSON Point, Polygon or MultiPolygon. It stays null until a boundary source is chosen (open question Q1 in `docs/open-questions.md`). | Boundary dataset (not yet chosen). | Phase 1 |
| `centroid` | `Coordinates`, nullable | degrees (WGS84) | Representative point, longitude first. It is used for "is this place inside this box" checks when present. | Reference data or boundary dataset. | Phase 1 |
| `status` | `active` \| `merged` \| `retired` | — | Lifecycle state. `merged` and `retired` are final: no later change is accepted. | Moderator decision. | Phase 1 |
| `status_reason` | `str` (1–500), nullable | — | Why the place was merged or retired. It is set exactly when `status` is not `active`. Leading and trailing spaces are removed. | Moderator. | Phase 1 |
| `merged_into_id` | `UUID` (v7), nullable | — | The place that replaced this one. It is set exactly when `status` is `merged`, and is never the place's own id. | Moderator. | Phase 1 |
| `version` | `int` (1 to 2 147 483 647) | count | Optimistic-concurrency version. It is 1 at creation and goes up by 1 with every change that has an effect. | Computed by the aggregate. | Phase 1 |
| `created_at` | `datetime` (UTC) | — | When the place was first recorded in Yakhnama. This is a system timestamp, not a historical date, so it has no `DatePrecision`. | Platform `Clock`. | Phase 1 |
| `updated_at` | `datetime` (UTC) | — | When the place last changed. It is never earlier than `created_at`. | Platform `Clock`. | Phase 1 |

## AdminLevel

The levels are listed from the top of the hierarchy down. The order of this list is the
order the domain uses.

| value | meaning | status |
|-------|---------|--------|
| `country` | A sovereign country. It has no parent. | glossary |
| `province_or_region` | A province or an administrative region, such as Gilgit-Baltistan. | glossary |
| `division` | A group of districts. Gilgit-Baltistan has divisions above its districts. | **proposed** (Q-G1) |
| `district` | A district. | glossary |
| `tehsil` | A tehsil, the sub-district level. | glossary |
| `union_council` | A union council. | glossary |
| `village` | A village or settlement. | glossary |

## PlaceName (value object)

One name for a place in one language and script (glossary: Place name).

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `text` | `str` (1–200) | — | The name. It is normalised to Unicode NFC and stripped of leading and trailing spaces, so a name typed with combining characters is the same as one typed precomposed. | Source of the name (see `source_id`). | Phase 1 |
| `language` | `LanguageCode` | — | BCP 47 subset: an ISO 639 language, optionally with an ISO 15924 script subtag, for example `en`, `ur`, `scl`, `bsk`, `bft`, `wbl`, `khw` or `ur-Arab`. Normalised to lower-case language and title-case script. The code list is **proposed** (Phase 1 plan, Q5). | Source of the name. | Phase 1 |
| `script` | `ScriptCode`, nullable | — | ISO 15924 script: `Latn`, `Arab` or `Tibt` (**proposed** list, Q-G3). It is null when not recorded. If `language` has a script subtag, the two must agree. | Source of the name. | Phase 1 |
| `kind` | `official` \| `alternative` \| `historical` \| `transliteration` | — | The name's role: the official form, another current form, a former name, or a transliteration into another script. The default is `official`. | Source of the name. | Phase 1 |
| `is_preferred` | `bool` | — | Whether this is the display name for its language. There is at most one preferred name per language (Q-G5). | Moderator or reference data. | Phase 1 |
| `source_id` | `UUID` (v7), nullable | — | The provenance `Source` the name comes from. Only the id is stored, because the provenance module arrives in Phase 3. | Provenance module (Phase 3). | Phase 1 |

## PlaceGeometry (value object)

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `geojson` | GeoJSON `Point` \| `Polygon` \| `MultiPolygon` | degrees (WGS84, EPSG:4326) | The footprint, longitude first. It holds at least one and at most 1 000 000 positions. Every position is finite and inside WGS84 bounds. Positions are two-dimensional only, because altitude has no meaning for an administrative footprint. | Boundary dataset (not yet chosen, Q1). | Phase 1 |

## Events

Every event carries `event_id`, `occurred_at` (UTC), `aggregate_id` (the place id),
`aggregate_type` (always `place`), `place_code` and `version` (the place's version
after the change). No event carries personal data, because place names, codes and
geometry are public reference data.

| event_type | extra fields | emitted when |
|------------|--------------|--------------|
| `geography.place_created` | `level`, `parent_id`, `names`, `geometry_type`, `centroid` | `PlaceFactory.create` records a new place (version 1). |
| `geography.place_name_added` | `name` | `Place.add_name` adds a name. |
| `geography.place_preferred_name_changed` | `language`, `previous_text` (nullable), `text`, `script` | A name becomes preferred, through `add_name` with a preferred name or through `set_preferred_name`. The previous preferred name in that language is demoted in the same change. |
| `geography.place_geometry_changed` | `previous_geometry_type`, `geometry_type`, `bounding_box` | `Place.set_geometry` sets, replaces or removes the geometry. The event holds the type and bounding box, not the full geometry. |
| `geography.place_centroid_changed` | `previous_centroid`, `centroid` | `Place.set_centroid` sets, replaces or removes the centroid. |
| `geography.place_retired` | `reason` | `Place.retire`. |
| `geography.place_merged` | `target_id`, `reason` | `Place.merge_into`. |

A method asked to make a change that is already in effect (the same geometry or
centroid, or a name that is already preferred) returns the place unchanged. It emits no
event and does not change the version.

## Place reference file (`data/reference/*.yaml`, schema version 1)

These are the fields of the versioned reference file after parsing. The loader that
reads YAML lives outside the domain. A file is self-contained: every `parent_code` names
an entry in the same file (**proposed**).

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `schema_version` | `1` | — | Version of the file format. Only `1` exists. | File author. | Phase 1 |
| `data_version` | `str` (1–32) | — | Version of the data, for example `0.1.0`. | File author. | Phase 1 |
| `source` | `str` (1–500) | — | Citation for the file as a whole. | File author. | Phase 1 |
| `licence` | `str` (1–200) | — | Licence the data is published under. | File author. | Phase 1 |
| `entries[].code` | `PlaceCode` | — | As `Place.code`. Unique within the file. | File author. | Phase 1 |
| `entries[].level` | `AdminLevel` | — | As `Place.level`. | File author. | Phase 1 |
| `entries[].parent_code` | `PlaceCode`, nullable | — | Code of the enclosing entry. It is null only for a country. The parent's level must be strictly higher. | File author. | Phase 1 |
| `entries[].names[]` | `text`, `language`, `script`, `kind`, `is_preferred`, `source` | — | As `PlaceName`, plus `source` (a text citation, 1–500 characters). `source` is **required for every language except English**, so no local-language label ships on a guess (Phase 1 plan). The text citation is not copied into `PlaceName.source_id` until provenance exists (Q-G7). | Cited source per name. | Phase 1 |
| `entries[].centroid` | `{longitude, latitude}`, nullable | degrees (WGS84) | As `Place.centroid`. It must lie inside `bbox` when both are given. | File author. | Phase 1 |
| `entries[].bbox` | `{min_longitude, min_latitude, max_longitude, max_latitude}`, nullable | degrees (WGS84) | An approximate extent. It is **not** turned into a place geometry, because a placeholder rectangle is not a boundary (Q-G6). | File author. | Phase 1 |
| `entries[].status` | `sourced` \| `proposed` \| `fixture` | — | How far the entry can be trusted: taken from the cited `source`, proposed and awaiting confirmation, or test fixture data that makes no claim about the world. This is data-quality status, not the place lifecycle `Place.status`. | File author. | Phase 1 |
| `entries[].source` | `str` (1–500), nullable | — | Citation for the entry. It is required when `status` is `sourced`. | File author. | Phase 1 |

## Open questions raised by this module

| # | Question | Proposed default | Blocking |
|---|----------|------------------|----------|
| Q-G1 | Should `division` be a level of the hierarchy? The glossary lists country → province/region → district → tehsil → union council → village, but Gilgit-Baltistan groups its districts into divisions. | Keep `division` between `province_or_region` and `district`. | no |
| Q-G2 | What scheme do place codes follow? | Lower-case dotted path from the country, such as `pk.gb.hunza`, used only as a convention. Codes never change after publication, even if a place is re-parented. | no |
| Q-G3 | Which scripts do place names need? | `Latn`, `Arab`, and `Tibt` for the occasional Tibetan-script Balti. Add others only when a sourced name needs them. | no |
| Q-G4 | Must a parent be exactly one level above its child? | No. The parent must be strictly higher and gaps are allowed, because tehsils and union councils are not recorded everywhere. | no |
| Q-G5 | How many preferred names may a place have? | At most one per language, possibly none. Display falls back to the first-recorded name in the language, then to the caller's fallback languages. | no |
| Q-G6 | Should a placeholder `bbox` in reference data become the place geometry? | No. It stays in the reference file only, and `geometry` waits for the boundary source (Q1). | no |
| Q-G7 | How do textual name citations in reference data become provenance `Source` records? | Keep them in the YAML. Link them to `PlaceName.source_id` when the provenance module arrives in Phase 3. | no |
| Q-G8 | Must every non-country place have a parent inside the data set? For example, a regional fixture that omits the country could not be loaded. | Yes. Reference files include the country entry. | no |
