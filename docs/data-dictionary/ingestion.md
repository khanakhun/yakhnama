# Data dictionary: ingestion

The `ingestion` module records what Yakhnama takes in from other publishers. It holds
the dataset catalog (`Dataset` → `DatasetVersion` → `IngestionRun`), the narrow
observation time series and the STAC-aligned raster asset catalog. It was introduced
in Phase 4. Column conventions are in [README.md](README.md). **Proposed** marks a
default the maintainer has not confirmed yet. The open questions at the end of this
page list each one.

Source code: `src/yakhnama/modules/ingestion/domain/`.

## Principles

- **Never ingest without a licence.** A `Dataset` cannot exist without a
  `DatasetLicence`, and `DatasetFactory.register` refuses a missing licence with
  `LicenceRequiredError`. The catalog reference file (`data/reference/datasets.yaml`)
  cannot describe a dataset without one either.
- **Every observation points at exact bytes.** An observation belongs to one
  `DatasetVersion`, which is pinned by the SHA-256 of its input, and names the
  `IngestionRun` that wrote it.
- **Observations are narrow and append-only.** One row is one value of one variable at
  one site and instant. The natural key starts with `observed_at`, so the table can
  become a TimescaleDB hypertable without an API change. A correction is a new dataset
  version, never an update.
- **Rasters never go into PostgreSQL.** A `RasterAsset` stores STAC-aligned metadata
  and hrefs (object-storage keys or URLs). The bytes, for example COGs, live in object
  storage.
- **Runs are never rewritten.** A finished run is terminal. A retry is a new run, so
  the record of the first attempt stays.
- **Third-party text stays out of events.** Events carry ids, codes, statuses,
  checksums and counts. Descriptions, licence texts, issue messages and values stay on
  the records.

| field | type | unit | meaning | provenance | since |

| `spdx_id` | `str` (`^[A-Za-z0-9.+-]{2,64}$`), nullable | — | SPDX licence identifier, for example `CC-BY-4.0`. Only the shape is checked. Exactly one of `spdx_id` and `custom_text` is set. | The publisher's stated licence. | Phase 4 |

### Dataset status transitions (**proposed**, Q-I3)

| from | allowed to |
|------|------------|
| `active` | `deprecated`, `retired` |
| `deprecated` | `retired` |
| `retired` | — (terminal) |

Only `active` datasets accept new versions, runs and raster assets. Deprecating or
retiring twice is a no-op with no event. A retired dataset's coverage can no longer
change. Datasets are never deleted.

| method | effect | refused when |
|--------|--------|--------------|
| `DatasetFactory.register(details)` | Creates an active dataset at version 1 and `DatasetRegistered`. Code uniqueness is checked by the command handler. | `details.licence` is missing (`LicenceRequiredError`). |
| `Dataset.deprecate()` | `active` → `deprecated`, `DatasetStatusChanged`. | The dataset is retired (`DatasetStatusError`). |
| `Dataset.retire()` | → `retired`, `DatasetStatusChanged`. | Never. |
| `Dataset.update_coverage(spatial, temporal)` | Replaces both coverages; `null` clears one. `DatasetCoverageUpdated` names the changed fields. | The dataset is retired (`DatasetStatusError`). |

`DatasetVersionFactory.record(dataset, details)` refuses datasets that are not active.

| `version` | `int` (1 to 2 147 483 647) | count | Optimistic-concurrency version. | Computed by the aggregate. | Phase 4 |
| `updated_at` | `datetime` (UTC) | — | When the run last changed. | Platform `Clock`. | Phase 4 |

### Run transitions

| from | allowed to |
|------|------------|
| `pending` | `running`, `failed` |
| `running` | `succeeded`, `partially_succeeded`, `failed` |
| `succeeded`, `partially_succeeded`, `failed` | — (terminal; a retry is a new run) |

Outcome rules (**proposed**, Q-I4):

- `succeeded`: the report has no errors and `counts.invalid` is 0. Warnings are allowed.
- `partially_succeeded`: at least one record persisted, and at least one error or
  invalid record.
- `failed`: at least one error, so a failure always says why.

| method | effect | refused when |
|--------|--------|--------------|
| `IngestionRunFactory.start(dataset, version, request)` | Creates a `pending` run and `IngestionRunRequested`. | The version belongs to another dataset (`VersionDatasetMismatchError`); the dataset is not active (`DatasetStatusError`). |
| `IngestionRun.start()` | `pending` → `running`, sets `started_at`, `IngestionRunStarted`. Not idempotent: a second start is a queue bug. | Not pending (`RunStateError`). |
| `IngestionRun.succeed(report, input_checksum)` | → `succeeded`, `IngestionRunFinished`. | Not running (`RunStateError`); the report does not fit (`RunOutcomeError`). |
| `IngestionRun.partially_succeed(report, input_checksum)` | → `partially_succeeded`, `IngestionRunFinished`. | As above. |
| `IngestionRun.fail(report, input_checksum=None)` | → `failed`, `IngestionRunFinished`. | Already finished (`RunStateError`); the report has no error (`RunOutcomeError`). |

### RunCounts

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `fetched` | `int` ≥ 0 | count | Raw records received from the source. | The pipeline's `fetch` and `parse` hooks. | Phase 4 |
| `parsed` | `int` ≥ 0 | count | Records turned into source-shaped rows. `≤ fetched`. | `parse` hook. | Phase 4 |
| `valid` | `int` ≥ 0 | count | Rows that passed validation. `≤ parsed`. | `validate` hook. | Phase 4 |
| `invalid` | `int` ≥ 0 | count | Rows that failed validation. `valid + invalid ≤ parsed` (**proposed**). | `validate` hook. | Phase 4 |
| `deduplicated` | `int` ≥ 0 | count | Valid records dropped as duplicates. `deduplicated + persisted ≤ valid` (**proposed**). | `deduplicate` hook. | Phase 4 |
| `persisted` | `int` ≥ 0 | count | Records written to storage. `≤ valid`. | `persist` hook. | Phase 4 |

The sums use `≤`, not `=`, because a failed run can stop part-way through a stage.
Every count fits a PostgreSQL `bigint`.

## Observation (entity, not an aggregate)

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `dataset_version_id` | `UUID` (v7) | — | The dataset version the value came from. | The pipeline. | Phase 4 |
| `station` | `StationRef`, nullable | — | The station, for station data. Exactly one of `station` and `grid_cell` is set. | The publisher. | Phase 4 |
| `grid_cell` | `GridCellRef`, nullable | — | The grid cell, for gridded data. | The publisher. | Phase 4 |
| `variable` | `str` (`^[a-z][a-z0-9_]{1,63}$`) | — | A code from the variable registry below. | The pipeline's mapping of the source column. | Phase 4 |
| `value` | `Measurement`, nullable | registry unit | The value in the variable's registry unit, converted in `normalise`. `null` exactly when `quality` is `missing`, so a publisher's fill value (for example `-9999`) is never stored as if it were measured (**proposed**, Q-I6). | The publisher, converted to SI. | Phase 4 |
| `observed_at` | `DateWithPrecision` | — | When the value was observed, with precision. | The publisher. | Phase 4 |
| `quality` | `QualityFlag` | — | `good`, `suspect`, `missing` or `estimated` (**proposed**, Q-I5). Each pipeline documents how it maps the publisher's flags. | The publisher's flags, mapped. | Phase 4 |
| `ingested_run_id` | `UUID` (v7) | — | The run that wrote it (lineage). | The pipeline. | Phase 4 |

**Natural key** (`ObservationKey`): `(observed_at, dataset_version_id, variable,
site_ref)`, with `observed_at` first so TimescaleDB can partition by time (**proposed**,
plan §5). `site_ref` is `station:<code>` or `grid_cell:<id>`, so a station and a cell
with the same code never collide. The precision of `observed_at` is not part of the
key: two values for the same instant are the same observation.

Construction raises a Pydantic validation error for an unknown variable or a wrong
unit. Code that wants the domain errors (`UnknownVariableError`,
`ObservationUnitMismatchError`) calls `require_variable_unit(variable, unit)` first.

### Variable registry (`VARIABLES`, **proposed**, plan §5)

| code | unit | meaning |
|------|------|---------|
| `air_temperature` | `kelvin` (K) | Air temperature. The CSV fixture in °C is converted in `normalise`. |
| `precipitation_depth` | `metre` (m) | Precipitation expressed as a depth of liquid water. |
| `discharge` | `cubic_metre_per_second` (m^3/s) | Volume of water flowing past a point per unit of time. |
| `snow_depth` | `metre` (m) | Depth of snow on the ground. |

Measurement heights, accumulation periods and averaging windows are deliberately not
defined here. They are source facts to be confirmed per dataset (Q-I7).

## RasterAsset (aggregate root)

| field | type | unit | meaning | provenance | since |
|-------|------|------|---------|------------|-------|
| `id` | `UUID` (v7) | — | Stable identity. | Platform `IdGenerator`. | Phase 4 |
| `dataset_version_id` | `UUID` (v7) | — | The dataset version it belongs to. | The cataloguing handler. | Phase 4 |
| `stac_id` | `str` (`^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`) | — | The STAC item id (**proposed** shape). | The publisher or the pipeline. | Phase 4 |
| `footprint` | `RasterFootprint` (GeoJSON `Polygon` or `MultiPolygon`) | — | The area covered, WGS84, two-dimensional, at most 100 000 positions (**proposed**). | The publisher's metadata. | Phase 4 |
| `acquired_at` | `DateWithPrecision` | — | When the scene was acquired (STAC `datetime`). | The publisher's metadata. | Phase 4 |
| `platform` | `str` (1–64, safe text) | — | The satellite or instrument platform (STAC `platform`). | The publisher's metadata. | Phase 4 |
| `cloud_cover` | `float` (0–100), nullable | % | Share of the scene covered by cloud (STAC `eo:cloud_cover`). | The publisher's metadata. | Phase 4 |
| `bands` | list of `StacBand` (≤ 256, unique names) | — | Band `name`, optional `common_name` (STAC `eo:common_name`, shape-checked only) and `description`. | The publisher's metadata. | Phase 4 |
| `assets` | list of `StacAsset` (1–32, unique keys) | — | Files of the item: `key`, `href`, `media_type` and `roles` (unique, ≤ 16). | The publisher or our object storage. | Phase 4 |
| `version` | `int` | count | Optimistic-concurrency version. | Computed by the aggregate. | Phase 4 |
| `created_at`, `updated_at` | `datetime` (UTC) | — | When it was catalogued and last changed. | Platform `Clock`. | Phase 4 |

`StacAsset.href` is either an object-storage key (relative, no leading `/`, no `.` or
`..` segments, no backslashes) or an `http`, `https` or `s3` URL with a host and no
user information. Whitespace is refused (**proposed**, Q-I9). `media_type` is a
lower-case media type with optional parameters; `COG_MEDIA_TYPE` is
`image/tiff; application=geotiff; profile=cloud-optimized`.

### STAC item output (`RasterAsset.to_stac_item_dict()`)

A documented serialisation boundary: JSON for STAC clients, never read back into the
domain. Aligned to STAC 1.1.0 with the EO extension v2.0.0 (**proposed**, Q-I10).

| key | value |
|-----|-------|
| `type` | `"Feature"` |
| `stac_version` | `"1.1.0"` |
| `stac_extensions` | The EO extension schema URL when `cloud_cover` or any band `common_name` is set, otherwise empty. |
| `id` | `stac_id` |
| `geometry` | `footprint` as GeoJSON. |
| `bbox` | `[min_longitude, min_latitude, max_longitude, max_latitude]` of the footprint. |
| `properties.datetime` | Start of the acquisition period, RFC 3339 in UTC (`Z`). |
| `properties.start_datetime`, `properties.end_datetime` | Present only when the precision is coarser than `exact`: the first and last instant of the period. |
| `properties.yakhnama:datetime_precision` | The `DatePrecision` of `acquired_at`. |
| `properties.platform` | `platform` |
| `properties.eo:cloud_cover` | `cloud_cover`, when known. |
| `properties.bands` | `name`, `description` and `eo:common_name` per band, when there are bands. |
| `links` | Empty. The API adds `self`, `collection` and `root` links, because they depend on where the catalog is served. |
| `assets` | `{key: {href, type, roles}}` |

## Reference file (`data/reference/datasets.yaml`)

Validated by `DatasetReferenceFile` (`schema_version: 1`, at most 1000 entries, unique
codes). Each `DatasetReferenceEntry` has the `DatasetDetails` fields (`code`, `title`,
`publisher`, `licence` as a nested `{spdx_id | custom_text, url, attribution}` object,
`update_frequency`, `description`, `homepage_url`, `spatial_coverage`,
`temporal_coverage`) plus `status` (default `active`), `is_fixture` (`true` for
synthetic test data that must never be published as real), `source` (a citation of the
publisher's documentation, `proposed`, or `synthetic fixture`) and `notes`. `licence`
is required. Entries are never removed.

## Open questions raised by this module

| # | Question | Proposed default | Blocking |
|---|----------|------------------|----------|
| Q-I1 | Is an attribution text required even for public-domain (CC0) datasets? | Yes. The open dataset cites every source it contains. | no |
| Q-I2 | May a dataset's licence change between releases? | No. Different terms mean a new dataset code, so each observation's terms are unambiguous. | no |
| Q-I3 | May a deprecated dataset be reactivated, and may deprecated datasets still receive versions or runs? | No to both. Deprecation stops new data; replacement is a new dataset. | no |
| Q-I4 | Are the run outcome rules right (success allows warnings; partial needs at least one persisted record and a problem; failure needs an error)? | Yes. | no |
| Q-I5 | Which quality flags are needed, and how do they map to the flags of publishers such as PMD or ICIMOD? | `good`, `suspect`, `missing`, `estimated`; each pipeline documents its mapping. | no |
| Q-I6 | Are rows the publisher flags as missing stored at all? | Stored with `value: null` and `quality: missing`, so gaps are visible in the series. | no |
| Q-I7 | Which heights, accumulation periods and averaging windows apply to each variable? | Recorded per dataset from the publisher's documentation; not part of the registry. | no |
| Q-I8 | Which vertical datum do station elevations use? | The publisher's, noted in the dataset description until a field is needed. | no |
| Q-I9 | Are the asset href rules right (object key or `http`/`https`/`s3` URL, no whitespace)? | Yes. | no (security-relevant) |
| Q-I10 | Which STAC version and extensions to align to? | STAC 1.1.0 with EO v2.0.0. | no |
| Q-I11 | How is `(observed_at, dataset_version_id, variable_code, station_ref)` a primary key when grid-cell observations have no station? | Store the prefixed `site_ref` (`station:…` or `grid_cell:…`) as the key column; keep the station and cell details in their own columns. Decided by the persistence engineer in T4. | no |
